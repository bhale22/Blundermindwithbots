## What a TWA actually is

An Android app whose content is this site running full-screen in **Chrome itself**
(not a WebView). Chrome removes the address bar only if it can verify that
whoever signed the app controls this domain — that's what `assetlinks.json` is
for. Fail that check and the app still works but shows a URL bar.

## Steps

### 1. Decide the package name — this is permanent ✅ done

An Android package name can never be changed once published to Play. It doesn't
have to match a domain you own, but reverse-DNS of one you do is the convention:

    com.blundermindchess.app

### 2. Generate the project ✅ done

The generated project lives in [`android/`](android/) — `bubblewrap init` has
already run, and `enableNotifications` is off. To change any setting, edit
`android/twa-manifest.json` and re-run `bubblewrap update` from that directory.

### 3. Enrol in Play App Signing, and list BOTH fingerprints

Google re-signs the app with a key it holds, so the fingerprint users actually
receive is Google's, not your upload key's. Listing only the upload key is the
usual cause of a shipped TWA showing an address bar.

Get the upload key's fingerprint:

```
keytool -list -v -keystore android.keystore -alias android
```

Get the app signing key's from **Play Console → Setup → App integrity → App
signing key certificate**.

Then set both on Railway (comma-separated, no spaces):

    TWA_PACKAGE_NAME       com.blundermindchess.app
    TWA_CERT_FINGERPRINTS  <upload SHA-256>,<Play app signing SHA-256>

Confirm it went out correctly:

```
curl https://blundermindchess.com/.well-known/assetlinks.json
node scripts/verify-pwa.mjs        # with the server running on :3100
```

Enrolling in Play App Signing also means losing the local keystore is
recoverable — you can reset an upload key. Without it, losing the keystore ends
your ability to update the app.

### 4. Build and test

```
bubblewrap build
```

Install the APK on a real device and check:
- **no address bar** at the top (that is the assetlinks check passing)
- airplane mode → the app still opens and plays
- the Maia download survives a force-quit

### 5. Play Store

Needs a Play Console account (one-off $25), a privacy policy URL, a store
listing and screenshots. Play's "minimum functionality" policy rejects thin
website wrappers; this one qualifies because it runs a neural net and a chess
engine locally and works offline — which is worth stating in the listing.

## Second domain

buildabotchess.com would be a **separate** Play listing with its own package
name, its own key, and its own `TWA_CERT_FINGERPRINTS` entry. The server already
serves it a manifest with its own name. Only do this if you want two store
presences; one app is a reasonable start.

## Where this project should live

Recommend a separate repo. It shares no build tooling with the web app, ships on
a different cadence, and — the real reason — its signing keystore must never sit
in a repo that deploys to a public web host. The only link between them is
`assetlinks.json`, which is already handled here.
